## 1. Аутентификация и блокировка пользователей

### ❓ Заблокированный пользователь все равно может войти в систему
**Проблема:** `is_active=False` не блокирует пользователя.

**Решение:** Если используете собственное поле `is_block`, проверяйте его при логине. Либо используйте только `is_active` и проверяйте его в бэкенде аутентификации. Не смешивайте оба подхода.

---

### ❓ Разница между блокировкой и удалением пользователя
**Ответ:** Блокировка = `is_active = False` (пользователь остается в БД, но не может войти). Удаление = полное удаление записи из БД. Используйте блокировку для менеджеров.

---

### ❓ Письмо об успешном входе не отправляется
**Решение:**
- Проверьте настройки EMAIL в `settings.py` (нет дубликатов)
- Используйте `EMAIL_HOST_USER` из settings вместо явного email
- Убедитесь что EMAIL_BACKEND настроен правильно

```python
class MailingAttempt(models.Model):
    mailing = models.ForeignKey(Mailing, on_delete=models.CASCADE)
    recipient = models.ForeignKey(Recipient, on_delete=models.SET_NULL, null=True)
    attempt_time = models.DateTimeField(auto_now_add=True)
    status = models.CharField(max_length=20)

```

## 4. Отправка письма и настройка email

### ❓ Какие настройки EMAIL нужны для Yandex?
**Решение:**
```python
EMAIL_BACKEND = 'django.core.mail.backends.smtp.EmailBackend'

```
Используйте **пароль приложения**, а не основной пароль аккаунта!

---

### ❓ Как получить ответ почтового сервера?
**Решение:** Оберните отправку в try-except:
```python
try:
    send_mail(subject, message, from_email, [recipient])
    MailingAttempt.objects.create(
        mailing=mailing,
        status='Успешно',
        server_response='OK'
    )
except Exception as e:
    MailingAttempt.objects.create(
        mailing=mailing,
        status='Не успешно',
        server_response=str(e)
    )
```

**Ответ:** Да, для разработки используйте:

### ❓ Можно ли отправить всем получателям одним вызовом send_mail()?

## 6. ЖИЗНЕННЫЙ ЦИКЛ РАССЫЛКИ И СТАТУСЫ

### ❓ Как работают start_time и end_time? Рассылка одноразовая?
**Ответ:**
- Рассылка **одноразовая**
- `start_time` - когда можно начать отправку
- `end_time` - крайний срок завершения
- Отправка возможна только если текущее время между start_time и end_time
- Статус меняется динамически: Создана → Запущена → Завершена

---

### ❓ Механизм переключения статусов
**Решение:** Реализуйте метод `update_status()` в модели:
```python
def update_status(self):
    now = timezone.now()
    if now < self.start_time:
        new_status = 'Создана'
    elif self.start_time <= now <= self.end_time:
        new_status = 'Запущена'
    else:
        new_status = 'Завершена'

    if self.status != new_status:
        self.status = new_status
        self.save()
```

Вызывайте в `get_object()` DetailView:
```python
def get_object(self, queryset=None):
    obj = super().get_object(queryset)
    obj.update_status()
    return obj
```

## 8. ПРАВА ДОСТУПА И РОЛИ (МЕНЕДЖЕР)

### ❓ Как реализовать права менеджера?
**Решение:**
1. Создайте кастомные права в Meta модели:
```python
class Mailing(models.Model):
    # ... поля
    class Meta:
        permissions = [
            ('can_view_all_mailings', 'Can view all mailings'),
            ('can_disable_mailing', 'Can disable mailing'),
        ]
```

2. Создайте группу "Менеджеры" и назначьте права
3. В views проверяйте права:
```python
from django.contrib.auth.decorators import permission_required

@permission_required('mailings.can_disable_mailing')
def disable_mailing(request, pk):
    # ...
```

## 10. КОМАНДНАЯ СТРОКА И DJANGO MANAGEMENT COMMANDS

### ❓ Как создать команду для отправки рассылок?
**Решение:**
1. Создайте структуру:
```
app_name/
  management/
    __init__.py
    commands/
      __init__.py
      send_messages.py
```

2. В `send_messages.py`:
```python
from django.core.management.base import BaseCommand
from django.utils import timezone
from app_name.models import Mailing

class Command(BaseCommand):
    help = 'Отправка рассылок'

    def handle(self, *args, **options):
        now = timezone.now()
        mailings = Mailing.objects.filter(
            start_time__lte=now,
            end_time__gte=now,
            status='Создана'
        )
        for mailing in mailings:
            # логика отправки
            self.stdout.write(f'Отправлена рассылка {mailing.id}')
```

3. Запуск: `python manage.py send_messages`

---

### ❓ Откуда команда берет данные?
**Ответ:** Из базы данных через ORM:
```python

```

### ❓ Где собирать статистику?
**Решение:** В контроллере (view):
```python
class StatisticsView(TemplateView):
    template_name = 'statistics.html'

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context['total_mailings'] = Mailing.objects.count()
        context['active_mailings'] = Mailing.objects.filter(
            status='Запущена'
        ).count()
        context['total_recipients'] = Recipient.objects.count()
        return context
```

## 15. ОШИБКИ И ИСКЛЮЧЕНИЯ

### ❓ TypeError: home() takes 0 positional arguments but 1 was given
**Решение:** View-функция должна принимать `request`:
```python
# НЕПРАВИЛЬНО
def home():
    return render('home.html')

# ПРАВИЛЬНО
def home(request):
    return render(request, 'home.html')
```

---

### ❓ NoReverseMatch для 'password_reset_confirm'
**Решение:** Добавьте URL для восстановления пароля:
```python
from django.contrib.auth import views as auth_views

urlpatterns = [
    path('password-reset/', auth_views.PasswordResetView.as_view(),
         name='password_reset'),
    path('password-reset/done/', auth_views.PasswordResetDoneView.as_view(),
         name='password_reset_done'),
    path('reset/<uidb64>/<token>/', auth_views.PasswordResetConfirmView.as_view(),
         name='password_reset_confirm'),
    path('reset/done/', auth_views.PasswordResetCompleteView.as_view(),
         name='password_reset_complete'),
]
```
